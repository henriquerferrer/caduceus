# F2.10 — Caduceus's AWS and Vonage responses match the captured goldens

F2.1, F2.2, F2.5 and F2.6 are built from the providers' API models and SDK
source. F2.9 adds real responses. This item checks the emulation against
them structurally, and fixes any divergence.

## Spec
- **Surface:** a new `internal/server/golden_test.go` reading `e2e/golden/`,
  and the provider handlers wherever a divergence needs a fix.
- **Interfaces:** for each golden file, the test sends Caduceus the request
  that produced it (SNS ok: a Publish to a phone number; SNS error: a
  Publish to `12345`; End User Messaging error: a destination of `+1`; Vonage
  SMS error: no `to`; two-part: a 200-character text; Messages error: no
  `text`), then compares the status code, the `Content-Type`, and the body's
  structure: XML element paths, or JSON key paths with their value types
  (string, number, object or array). Ids, timestamps, prices and numbers are
  not compared by value.
- **Out of scope:** response headers beyond `Content-Type`; byte-for-byte
  equality; new operations; webhook and receipt shapes (F2.9 captures send
  responses only).

## Acceptance
- (server test) every golden in `e2e/golden/` has a passing structural
  comparison, and the test fails when a golden file has no comparison, so a
  new golden can't be skipped silently.
- (server test) any divergence found is fixed in the handler, with the
  golden as the test.
