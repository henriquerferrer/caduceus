# F2.6 — Vonage Messages API (sms channel) on api.nexmo.com, through the proxy

Vonage recommends the Messages API for new integrations
(https://developer.vonage.com/en/messages/guides/sms-migration-to-messages).
An unmodified app calling `vonage.messages.send` with `channel: "sms"`
captures it in Caduceus through the same proxy setup as F2.5. The Messages
API answers `202 {"message_uuid": …}`, and its errors are problem+json.

`api.nexmo.com` carries many other Vonage APIs, and the Messages API carries
other channels (WhatsApp, RCS, …), so only the sms channel of
`POST /v1/messages` is answered. The channel is in the body, so this uses
F2.3's predicate routes.

## Spec
- **Surface:** `internal/server/vonage.go` (+ tests),
  `internal/server/proxy.go`, `internal/server/server.go`,
  `internal/server/guard.go` (`refuse`), `e2e/vonage-node/`
  (`messages.mjs`), `e2e/e2e_test.go`, `README.md`.
- **Interfaces:**
  - `intercepted` matches `api.nexmo.com` and the Messages API's regional
    hosts (confirm their names from the Messages API spec's `servers` list
    and cite it). The predicate: `POST /v1/messages` whose JSON body has
    `channel: "sms"`. Everything else passes through byte-for-byte (F2.3).
  - `POST /v1/messages` is also served on the listener; there a non-sms
    channel answers 422 problem+json saying Caduceus emulates only sms.
  - Captured messages carry `Provider: "vonage-messages"`, `ID` = the
    returned `message_uuid` (a UUID), `StatusCallback` = the body's
    `webhook_url`. As in F2.5, `setStatus` posts nothing for it until F2.7.
  - Success is 202 with `{"message_uuid": …}` and an `X-Request-Id` header.
    Errors are problem+json (`type`, `title`, `detail`, `instance`): 401 with
    no `Authorization` header (a Bearer JWT or Basic of any value is
    accepted), 422 for a missing `to`, `from` or `text`, or a
    `message_type` other than `text`. `refuse` on `/v1/messages` answers 403
    problem+json naming `-allowed-hosts`.
- **Out of scope:** channels other than sms; JWT verification; message
  updates (`PATCH /v1/messages/{uuid}`); receipts (F2.7).

## Acceptance
- (server test) a valid sms body answers 202 with a UUID `message_uuid` and
  `X-Request-Id`, and the inbox holds one `vonage-messages` message with that
  id.
- (server test) 401 without `Authorization`, 422 for each missing field,
  each with a problem+json body; nothing captured.
- (server test, fake upstream) through the proxy: a `channel: "whatsapp"`
  message, `GET /v2/applications` and an oversize body reach the upstream
  unchanged; the sms message does not.
- (server test) guard: `/v1/messages` on the listener with an unknown Host,
  or a cross-site `Origin`, answers 403 problem+json.
- (server test) a `vonage-messages` capture is not a Twilio Messages resource.
- (e2e) the stock `@vonage/server-sdk` `vonage.messages.send` with an SMS
  message, under the F2.5 environment, resolves with a `messageUUID` that
  `/api/v1/wait` returns, with the code in `otp`; a send with no text makes
  the SDK throw.
- (README) the Vonage section lists the Messages API.
