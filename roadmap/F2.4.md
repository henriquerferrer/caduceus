# F2.4 — Proxy mode intercepts AWS SNS and End User Messaging hosts, passing every other action through

With `AWS_ENDPOINT_URL_SNS` set, every SNS call reaches Caduceus, so an app
that also uses SNS topics can't use it. In proxy mode Caduceus can instead
answer only the SMS sends on the real AWS hosts and forward every other
action to AWS unchanged, so topic calls keep working for SDKs that honour
`HTTPS_PROXY` (boto3, Go v2). The AWS JavaScript SDK ignores `HTTPS_PROXY`,
so it stays on the env-var path (F2.1, F2.2).

## Spec
- **Surface:** `internal/server/proxy.go` (`intercepted`),
  `internal/server/server.go` (`providerRoutes`), `internal/server/aws.go`,
  tests with a fake upstream, `README.md`.
- **Interfaces:**
  - `intercepted` also matches `sns.<region>.amazonaws.com` and the End User
    Messaging host. Confirm that host's form (`sms-voice.<region>.amazonaws.com`
    is inferred from the endpoint prefix) against the SDK's endpoint rules
    before matching it, and cite the source in a comment.
  - These hosts use F2.3's predicate routes. The predicate is: `Action=Publish`
    with a `PhoneNumber` and no `TopicArn`/`TargetArn`, or `X-Amz-Target:
    PinpointSMSVoiceV2.SendTextMessage`. Matching requests are answered by the
    F2.1 and F2.2 handlers; everything else passes through.
- **Out of scope:** a real-SDK e2e through the proxy. Go on macOS ignores
  `SSL_CERT_FILE`, so the Go and boto3 proof moves to F4 ("proxy mode
  verified from Python, Go, Ruby and curl"). Also out: AWS JS v3 through the
  proxy (the SDK ignores `HTTPS_PROXY`); FIPS, dual-stack and China-partition
  hosts.

## Acceptance
- (server test, fake upstream) through the proxy to
  `sns.us-east-1.amazonaws.com`: a Publish to a phone number is captured and
  never reaches the upstream; a Publish with `TopicArn`, a `ListTopics`, and a
  Publish whose body exceeds the cap all reach the upstream with a
  byte-identical body and the same end-to-end headers.
- (server test, fake upstream) the same split on the End User Messaging host,
  for `SendTextMessage` versus another target.
- (server test) a host such as `s3.us-east-1.amazonaws.com` is tunnelled, not
  intercepted.
- (README) proxy mode lists the AWS hosts, which actions are answered and
  that the rest go to AWS, and that the AWS JS SDK must use the env vars
  instead.
