# F2.2 — AWS End User Messaging SendTextMessage, through AWS_ENDPOINT_URL_PINPOINT_SMS_VOICE_V2

AWS End User Messaging SMS (service `pinpoint-sms-voice-v2`) is the newer AWS
SMS API, and what SNS SMS is delivered through. An unmodified app calling
`SendTextMessage` captures it in Caduceus when it runs with
`AWS_ENDPOINT_URL_PINPOINT_SMS_VOICE_V2=http://localhost:8026`.

The protocol is awsJson1_0: `POST /` with
`Content-Type: application/x-amz-json-1.0` and
`X-Amz-Target: PinpointSMSVoiceV2.SendTextMessage`, answered `{"MessageId": …}`
(https://docs.aws.amazon.com/pinpoint/latest/apireference_smsvoicev2/API_SendTextMessage.html).

## Spec
- **Surface:** `internal/server/aws.go` (+ `aws_test.go`), `e2e/aws-node/`
  (add `@aws-sdk/client-pinpoint-sms-voice-v2` and a `send-text.mjs`),
  `e2e/e2e_test.go`, `README.md`.
- **Interfaces:**
  - F2.1's `POST /{$}` dispatcher sends
    `X-Amz-Target: PinpointSMSVoiceV2.SendTextMessage` here. Any other target
    (`PinpointSMSVoiceV2.*` or not) keeps F2.1's 400
    `UnknownOperationException`, naming the target and saying Caduceus
    emulates only SendTextMessage.
  - Captured messages carry `Provider: "aws-sms-voice"`, `To` =
    `DestinationPhoneNumber`, `From` = `OriginationIdentity` (as given, even
    when it is a pool id or an ARN), `ID` = the returned `MessageId`.
  - Errors are JSON 1.0: HTTP 400, header `x-amzn-errortype` and body
    `{"__type":"ValidationException","Message":…,"Reason":…,"Fields":[…]}`,
    with the member casing of the service model, so the SDK fills its typed
    `Reason` and `Fields`.
- **Out of scope:** every other End User Messaging operation (phone numbers,
  pools, configuration sets, voice); `DryRun` beyond what Acceptance states;
  proxy-mode interception (F2.4).

## Acceptance
- (server test) a SendTextMessage with `DestinationPhoneNumber` and
  `MessageBody` answers 200 `{"MessageId": "<uuid>"}` with content type
  `application/x-amz-json-1.0`, and the inbox holds one `aws-sms-voice`
  message with that id and the body's code in `otp`.
- (server test) `ValidationException` (400) for a missing or non-E.164
  `DestinationPhoneNumber`, and for a `MessageBody` that is empty or longer
  than 1600 characters; nothing is captured.
- (server test) `DryRun: true` answers 200 with a MessageId and captures
  nothing (AWS validates a dry run without sending).
- (server test) an `aws-sms-voice` capture is not a Twilio Messages resource.
- (e2e) the stock `@aws-sdk/client-pinpoint-sms-voice-v2`
  `SendTextMessageCommand`, configured only by the env var, dummy credentials
  and a region, returns a MessageId that `/api/v1/wait` returns, with the
  code in `otp`; a send with no destination makes the SDK throw
  `ValidationException`.
- (README) the AWS section lists End User Messaging and its env var.
