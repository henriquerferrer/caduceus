# F2.1 — AWS SNS Publish to a phone number, through AWS_ENDPOINT_URL_SNS

An unmodified app that sends SMS with SNS `Publish` (`PhoneNumber` +
`Message`) captures it in Caduceus when it runs with
`AWS_ENDPOINT_URL_SNS=http://localhost:8026` and any credentials and region.
Every current official AWS SDK honours that variable (JS v3 ≥3.428, boto3
≥1.28, Go v2 config ≥1.21, Java v2 ≥2.28.1, Ruby core ≥3.178, .NET ≥3.7.108,
PHP ≥3.281, CLI ≥2.13: https://docs.aws.amazon.com/sdkref/latest/guide/feature-ss-endpoints.html).

SNS speaks the awsQuery protocol: a form-encoded `POST /` with
`Action=Publish&Version=2010-03-31`, answered with XML
(model: https://github.com/aws/api-models-aws/blob/main/models/sns/service/2010-03-31/sns-2010-03-31.json;
API: https://docs.aws.amazon.com/sns/latest/api/API_Publish.html).

This item also lays the groundwork every later F2 provider uses: providers
assign their own message ids, the Twilio Messages API stops seeing other
providers' captures, and the listener guard's refusals use the provider's
error shape.

## Spec
- **Surface:** a new `internal/server/aws.go` (+ `aws_test.go`),
  `internal/server/server.go` (the `POST /{$}` route on `s.mux`, `outbound`),
  `internal/server/guard.go` (`refuse`), `internal/server/twilio.go`
  (list/fetch filter), `e2e/aws-node/` (new fixture: `package.json` pinning
  `@aws-sdk/client-sns`, `publish.mjs`), `e2e/e2e_test.go`, `justfile` (the
  `e2e` recipe installs the fixture the way it installs `e2e/twilio-node`),
  `README.md`. No change under `.github/`.
- **Interfaces:**
  - `POST /{$}` (exact root, registered on `s.mux` only, never on the
    provider muxes) is the AWS dispatcher: a form body with an `Action` field
    goes to the SNS handler; a request with an `X-Amz-Target` header answers
    400 `{"__type":"UnknownOperationException","message":…}` naming the target
    (F2.2 then answers `PinpointSMSVoiceV2.SendTextMessage`); a request with
    neither answers 400 in the awsQuery error shape. `GET /` stays the UI, and
    every other path keeps today's answer.
  - `outbound()` keeps a non-empty `m.ID`, so each provider assigns its own id
    format; Twilio and generic sends still get an `SM…` sid.
  - Captured messages carry `Provider: "aws-sns"`, `From` = the
    `AWS.MM.SMS.OriginationNumber` or `AWS.SNS.SMS.SenderID` message
    attribute when given (else empty), `ID` = the `MessageId` returned (a
    UUID). `otp` comes from the body as for any non-Verify message.
  - `twilioResource(m)` is an allowlist (provider `twilio`, `generic` or
    `simulated`) and replaces the Verify-only test in `twilioFetch` and
    `twilioList`, so the Twilio Messages API never lists or fetches another
    provider's capture.
  - Errors are awsQuery XML with HTTP 400:
    `<ErrorResponse><Error><Type>Sender</Type><Code>…</Code><Message>…</Message></Error><RequestId>…</RequestId></ErrorResponse>`.
  - The F1.8 guard's `refuse` answers each route in its provider's error
    shape: on `POST /{$}`, awsQuery XML with code `AuthorizationError`, or
    JSON with `__type` `AccessDeniedException` when `X-Amz-Target` is set;
    Twilio routes as today; everything else as today. The message still says
    to add the host with `-allowed-hosts`. F2.5 and F2.6 add the Vonage
    shapes.
- **Out of scope:** proxy-mode interception of AWS hosts (F2.4); End User
  Messaging (F2.2); topics, subscriptions, FIFO and every other SNS action
  (refused, see Acceptance); AWS inbound / two-way SMS; delivery-status
  logging (SNS has no per-message callbacks); signature verification (any
  credentials are accepted).

## Acceptance
- (server test) `Action=Publish` with `PhoneNumber=+15551234567` and
  `Message` answers 200 with
  `<PublishResponse xmlns="http://sns.amazonaws.com/doc/2010-03-31/"><PublishResult><MessageId>…</MessageId></PublishResult><ResponseMetadata><RequestId>…</RequestId></ResponseMetadata></PublishResponse>`,
  and the inbox holds one `aws-sns` message whose id is that MessageId, with
  the body, the recipient and the OTP extracted from the body.
- (server test) the sender is taken from `MessageAttributes.entry.N` with
  `Name=AWS.MM.SMS.OriginationNumber` (preferred) or `AWS.SNS.SMS.SenderID`.
- (server test) refused with 400 and code `InvalidParameter`, capturing
  nothing: no `Message`; no `PhoneNumber` and no `TopicArn`; a `PhoneNumber`
  that is not E.164; a Publish with `TopicArn` or `TargetArn` (the message
  says Caduceus emulates only Publish to a phone number). Any other `Action`
  answers 400 `InvalidAction` with the same explanation.
- (server test) a `POST /` with an `X-Amz-Target` of `Foo.Bar` answers 400
  `UnknownOperationException` naming it; a `POST /` with neither an `Action`
  nor an `X-Amz-Target` answers 400 in the awsQuery shape;
  `POST /api/v1/nope` and `GET /nope` keep the answers they give on main.
- (server test) guard: a `POST /` with an unknown Host, or with a cross-site
  `Origin`, answers 403 in the awsQuery shape with code `AuthorizationError`
  and a message naming `-allowed-hosts`; with `X-Amz-Target` set, the JSON
  shape.
- (server test) an `aws-sns` capture is absent from the Twilio Messages API's
  list and answers 20404 on its fetch; `generic` and `simulated` messages are
  still listed as today.
- (e2e, `just e2e`) the stock `@aws-sdk/client-sns` `PublishCommand`, with
  only `AWS_ENDPOINT_URL_SNS`, dummy credentials and a region set, returns a
  MessageId that `/api/v1/wait` returns as the message id, with the code from
  the body in `otp`; a Publish with no phone number makes the SDK throw an
  error whose `name` is `InvalidParameterException` (the JS SDK's class for
  the wire code `InvalidParameter`, which the server tests assert in the XML
  `Code`). The test fails, not skips, in CI
  when the fixture is missing.
- (README) an AWS section: the env var; the SDK minimum versions; to set only
  the per-service variables, never the global `AWS_ENDPOINT_URL`; that other
  SNS actions are refused on the base URL. The Docker Compose example shows
  `AWS_ENDPOINT_URL_SNS=http://caduceus:8026` beside
  `CADUCEUS_ALLOWED_HOSTS`.
