# F1.8 — Should the local API refuse cross-site and rebound-host requests?

## Harm
A web page the developer opens while Caduceus runs can, by DNS rebinding to
127.0.0.1, read captured verification codes and SMS bodies, and can send
cross-site POSTs that approve or expire verifications. Steps on the default
branch: run Caduceus, visit a page that rebinds its hostname to 127.0.0.1:8026
and fetches `/api/v1/verifications` or `/2010-04-01/Accounts/x/Messages.json`.

## Notes
- From the F1 audit, record block 2 (`roadmap/audits/F1.md`); it also
  promotes the discovered note `local-rest-api-has-no-origin-or-host-check`
  (filed from F1.4). The exposure predates F1, which widened it with
  code-bearing routes (`/api/v1/verifications`, `verification` SSE events)
  and new write routes (`/api/v1/verifications/{sid}/expire`, Verify update
  and check). The provider routes are also served directly on the local
  listener (`internal/server/server.go`, the base-URL path), so the Messaging
  list `GET /2010-04-01/Accounts/{any}/Messages.json` is part of the same
  exposure; it returns every captured SMS body.
- Why it is a direction call and not a fix: a Host allowlist protects
  against DNS rebinding but breaks every client that reaches Caduceus by a
  name other than localhost — for example an app container calling
  `http://caduceus:8026/api/v1/wait` under docker compose. The README's
  Docker instructions only publish to 127.0.0.1 and do not mention compose,
  but nothing stops that setup. Which clients must keep working is a product
  decision. Requests arriving through the proxy carry the provider's Host by
  design and must stay exempt under any option; SDKs send no `Origin`, and
  base-URL clients send an allowed Host, so neither needs a route exemption.
- The audit did not test a real browser, so whether Chrome's or Firefox's
  private-network-access protections already block the rebinding read is
  open.

> **RECOMMENDATION (2026-10-26):** (b) — reject requests whose `Origin` (or
> `Sec-Fetch-Site: cross-site`) is not Caduceus's own origin, and check `Host`
> against localhost, 127.0.0.1 and [::1] plus names from a new
> `-allowed-hosts` / `CADUCEUS_ALLOWED_HOSTS` option, applied to every route
> on the local listener — the UI, `/api/v1/*` and the provider routes served
> there — and never to requests arriving through the proxy. It closes both
> the CSRF and the rebinding read, and gives Docker users an explicit
> one-line opt-in instead of a silent break.
