# F2.9 — Capture real AWS and Vonage responses as golden fixtures

## Hand-off
**Why this is yours:** it needs your AWS and Vonage accounts, a real phone
number and a few cents of credit. No agent has those, and only a real
provider can produce a real response. F2.10 then checks Caduceus against
what you capture.

**Before you start (AWS):** a new AWS account is in the SMS sandbox, where SNS
only sends to a verified number: verify YOUR_NUMBER first (SNS console →
Text messaging → Sandbox destination phone numbers). End User Messaging's
`SendTextMessage` usually needs an origination identity (a phone number or
sender id) in your account; if you have none, send to one of AWS's SMS
simulator destination numbers (End User Messaging console → Simulator), which
needs no origination number and costs nothing to deliver.

**Steps** (any order, about 30 minutes). In each command, replace YOUR_NUMBER,
SENDER, KEY and SECRET with your own values:
1. AWS SNS: `aws sns publish --phone-number YOUR_NUMBER --message "golden test 123456" --debug`.
   For the error, `aws sns publish --phone-number 12345 --message x --debug`
   (AWS rejects the number with `InvalidParameter`). From each debug output
   save the HTTP status, the response headers and the raw XML body.
2. AWS End User Messaging: `aws pinpoint-sms-voice-v2 send-text-message
   --destination-phone-number YOUR_NUMBER --message-body "golden test 123456" --debug`.
   For the error, use `--destination-phone-number +1` (rejected with
   `ValidationException`). Save the same.
3. Vonage SMS API: `curl -si -u KEY:SECRET -H 'Content-Type: application/json'
   -d '{"from":"SENDER","to":"YOUR_NUMBER","text":"golden test 123456"}' https://rest.nexmo.com/sms/json`;
   once more without `to`; and once with a text of about 200 characters.
4. Vonage Messages API: `curl -si -u KEY:SECRET -H 'Content-Type: application/json'
   -d '{"channel":"sms","message_type":"text","from":"SENDER","to":"YOUR_NUMBER","text":"golden test 123456"}'
   https://api.nexmo.com/v1/messages`, and once without `text`.
5. Redact account ids, keys, phone numbers and balances, replacing them with
   obviously fake values in the same format. Save each response as
   `e2e/golden/<api>-<case>.http` (status line, headers, a blank line, the
   body), and open a PR with the files.

**Done when:** `e2e/golden/` on main holds the 9 files (SNS ok and error, End
User Messaging ok and error, Vonage SMS ok, error and two-part, Messages ok
and error), with no real credential, account id or phone number in them.
