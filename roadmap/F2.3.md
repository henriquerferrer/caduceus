# F2.3 — Body-aware routing in proxy mode, with byte-identical pass-through

Proxy mode routes an intercepted host's requests by method and path: an
emulated route is answered, everything else is passed to the real provider.
AWS (F2.4) and the Vonage Messages API (F2.6) name the operation or channel
in the request body or headers, not the path, so an emulated route needs a
predicate over the request, and a request that fails it must reach the
provider exactly as the SDK sent it (SigV4 signs the payload hash).

This item builds only the mechanism. F2.4 and F2.6 wire providers to it.

## Spec
- **Surface:** `internal/server/server.go` (`serveProvider`,
  `providerRoutes`), `internal/server/proxy.go`, tests with a fake upstream.
- **Interfaces:**
  - A provider route may carry a predicate
    `func(r *http.Request, body []byte) bool`. For such a route the request
    body is buffered up to 1 MiB; the predicate sees the headers and the
    buffered body; the handler then reads the same body again.
  - When the predicate is false, or the body is larger than the cap, the
    request is forwarded upstream with its body byte-for-byte unchanged, its
    `Content-Length` intact, and every end-to-end header unchanged
    (hop-by-hop headers are handled as `ReverseProxy` does today).
  - Routes without a predicate behave exactly as today.
- **Out of scope:** any provider host (F2.4, F2.6); request bodies over the
  cap being inspected; verifying signatures.

## Acceptance
- (server test, fake upstream, a test-only route table) a request whose body
  matches the predicate is answered by the route's handler, which receives
  the full body, and never reaches the upstream.
- (server test) a non-matching request, and a 2 MiB request, reach the
  upstream with a byte-identical body, the same `Content-Length`, and the
  same end-to-end headers.
- (server test) path-only routes (the existing Twilio and Verify ones) are
  unchanged: the existing proxy tests pass without edits.
