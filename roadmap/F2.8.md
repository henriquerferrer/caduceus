# F2.8 — Simulated inbound messages in Vonage's shapes, from the API and the inbox

`POST /api/v1/inbound` and the inbox's "Send reply" form post a Twilio-shaped
webhook to the app. A Vonage app needs Vonage's inbound shape, which differs
between the SMS API and the Messages API.

## Spec
- **Surface:** `internal/server/server.go` (`handleInbound`),
  `internal/server/vonage.go`, `internal/server/ui/index.html` (the reply
  form), tests, `e2e/ui/inbox.spec.mjs`, `README.md`.
- **Interfaces:**
  - `POST /api/v1/inbound` takes an optional `"provider"`: `"twilio"`
    (default, today's behaviour, stored as `simulated`), `"vonage-sms"` or
    `"vonage-messages"`. Any other value answers 400 and stores nothing.
  - A Vonage inbound message is stored with that provider and with the id the
    webhook carries, in the provider's format (the SMS API's `messageId`, the
    Messages API's UUID `message_uuid`).
  - SMS API shape: POST JSON with `msisdn` (sender), `to`, `messageId`,
    `text`, `type: "text"`, `keyword` (first word, uppercased),
    `message-timestamp`.
  - Messages API shape: POST JSON with `to`, `from`, `message_uuid`,
    `timestamp` (ISO 8601), `channel: "sms"`, `message_type: "text"`, `text`.
  - Timestamps come from the store's clock, in UTC. The webhook URL is the
    request's `webhook`, else `-inbound-webhook`, as today.
  - The inbox's reply form sends the provider of the thread's latest outbound
    message when it is `vonage-sms` or `vonage-messages`, and none otherwise.
- **Out of scope:** signing; concatenated-part fields; a separate default
  inbound webhook per provider; AWS inbound / two-way SMS (an `aws-*` value
  answers 400); checking webhook shapes against real ones.

## Acceptance
- (server test, test webhook server, injected clock) each provider value
  posts its shape with the given from, to and text and the injected time;
  the stored message's id equals the webhook's `messageId` or
  `message_uuid`; the response's `webhook_status` is the webhook's status.
- (server test) no `provider` posts exactly today's Twilio form (the existing
  tests pass unchanged); `provider: "aws-sns"` and an unknown value answer 400
  and store nothing.
- (browser, `e2e/ui`) replying in a thread whose latest outbound message is
  `vonage-sms` posts a request with `provider: "vonage-sms"`; replying in a
  Twilio thread sends no provider; the axe scan still passes.
- (README) the inbound row documents `provider`.
